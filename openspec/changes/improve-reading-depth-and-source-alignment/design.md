## Context

动机与范围见 proposal.md。已归档的上一轮实现提供单主 agent、有界工具循环、应用自有 MCP、分层 prompt、来源注册表和 schema v3。

本轮代码调查确认：

- `prompts.ts` 同时存在“默认只输出一个定义句”“句末即结束”和通常一至两个短段的要求，直接抑制解释深度；多个回答出口共享这些契约。
- `reading-engine.ts` 的正常与引用修复出口固定请求 1200 输出 tokens；`conversations.ts` 也以 1200 预留窗口，需要统一而非只放宽文案。
- `buildChunks` 将章节页拼接后分块，却把每个 chunk 的 `pageNumber` 设为章节第一页，`source_pages` 填整个章节，且字符偏移为空。这是增长投资案例 41–42 页被标成 26 页的已确认原因。
- 词汇标记直接拆分 PDF.js 文字节点并插入 `mark`。canvas 与文字层分别处理尺寸和缩放。两者是几何问题的调查入口，尚无足够复现证据证明唯一根因；不得把猜测写成已修复结论。
- 当前段落缓存只能在页眉打开，未提供精确原文范围标记。旧数据可能缺乏足以唯一定位的 anchor。

## Goals / Non-Goals

**Goals:**

- 把回答质量目标从“短、ID 合法”提升为解释充分、事实审慎、来源支持且位置准确。
- 不扩大默认历史、不传整书、不强制每问联网；长解释的输出额度与全局预算共同核算。
- 将内容身份、真实位置、界面标签和记录范围分开，避免展示样式反过来决定数据身份。
- 保持原 PDF、原文字映射、用户笔记、进度与旧回答可恢复；坐标修复与新标记样式分别验收。

**Non-Goals:**

- 不新增通用 prompt DSL、向量数据库、评审 agent 或模型供应商角色；不把开发评测循环放进每次用户问答。
- 不用 OCR 推断字形，不通过重画文字或改变 PDF 正文来制造选区对齐。
- 不把旧答案自动重生成，不执行本轮讨论之外的用户数据清理。

## Decisions

### 1. 直接开头与解释主体使用同一契约

保留单句定义／短段结论，但移除默认单句结束、禁止背景和全局短段上限。词汇主体选择有用维度：含义与机制、计算、示例、应用、易混点、局限。解读主体选择论证链、因果机制、前提、反例及实际含义。维度不是固定标题，也不要求每次全部输出；普通请求默认有实质展开，明确“只要一句话”时才收缩。

任务、格式、证据策略版本分别更新。所有 direct/native/JSON/free-text/finish/limit-synthesis 与有界引用修复出口都使用一致契约；用户补充问题优先。用少量对照示例展示“内容完整但不啰嗦”，避免长篇金融示例把所有领域套成财务分析。

**替代方案**：仅增加最小字数或固定六个模块容易凑字、捏造轶事；用任务覆盖和案例标注约束质量，不以篇幅当质量代理。必要否定与会计条件不做正则删改。

### 2. 解释与事实核验分别判断充分性

主 agent 同时考虑作者原意覆盖、解释缺口和事实核验需求，不把“可复述”当成“充分”。书中定义、公式、因果和经验性结论依各自证据检查条件。明确核验、最新事实、有实质理由的可疑／片面论断触发定向 MCP；没有核验缺口的稳定概念仍可零搜索。

优先相关原始研究、标准／监管与可信专业资料，不把域名白名单、搜索排名或更新时间当真伪证明；网页中的监管断言、具体数值、争议及引语需读取支持段落，snippet 不冒充全文。比较定义、口径、年代、样本、因果与相关性，综合成观点而非并列复述来源。无网、无结果、故障和预算耗尽保留不同状态和真实缺口。

**替代方案**：每次解读强制联网浪费时间且可能引入低质量资料；让模型只信书又会放大原文错误。采用具体论断驱动，复用既有硬权限、去重、无进展停止与预算，不增加必经 planner/judge。

### 3. 单一输出额度与上下文窗口核算

将默认详细解释的输出预留集中为任务策略，初始普通解释上限拟为 2400 tokens，明确简答 600 tokens；复杂解读只在现有可用总预算内扩大，不改变默认 24000 累计 token 或 180 秒时限。这里是容量上限，不是要求模型写满。

同一额度用于阅读入口、工具循环最终回答、综合／修复及模型窗口检查。动态剩余额度不足时先缩减可选证据和历史，不截断必要选区／问题；不能完整生成时如实标记受限／不完整，不作为完整解释缓存。评测记录 truncation、完成状态及逐调用用量，依据实测调整常量，不能静默改变总预算。

### 4. 分块保留可逆的页与字符边界

在拼接／归一化时保留每段文本到原页偏移的映射，分块和 overlap 从这些映射派生位置。chunk 元数据仅包含自身覆盖的 page spans，而非全章页列表。跨页检索摘录保留 page ranges；引用可以指向其中更精确的已知子段，不能根据模型口述页码选定位。

`SourceReference` 增量支持结束页、位置状态和可用段落／字符范围，`page` 继续表示一基 PDF 物理页，范围起点为首个实际证据页。不以印刷页脚数字推算 PDF 页码。来源 ID 与可修正定位分离，保留旧 ID／解析别名，不因 UI 改成 Pxx 全量重编号。

对旧 chunk 建立带版本的本地修复／重建派生索引，保证重复执行幂等。对旧引用使用限定文档的摘录、前后文和已知页范围验证唯一位置，保存解析结果及原始元数据；不能唯一证明的位置显示待核实。索引重建前备份，事务替换派生数据；不得删除旧消息、笔记或改变原 PDF。用户页码跳转本身仍可用，但不把一个未经验证的旧引用伪装成精确目标。

**替代方案**：全部 chunk 简单写成当前阅读页会让跨书与旧历史错误；全部按单页切块容易截断论证。本方案保留跨页上下文并提供位置映射，位置不明时宁可显式降级。

### 5. 引用标签由验证后的来源投影

共享引用组件显示 BookOpen＋`P41`／`P41–42`，无可靠位置显示“原文”；Globe＋短标题，缺失时域名。网页标题用 CSS 限宽末尾省略，保留完整可访问名称、标题、域名和安全 URL。默认最大文字宽度拟 10em 且受容器约束，不按视口缩放字体。

来源详情沿用 portal、视口裁剪和稳定组件身份，兼容键盘、窄侧栏、流式半 marker、相同页不同书及多引用换行。旧数字 marker 的显示改为来源投影，不改历史 Markdown。复制、保存、导出保留完整标题、验证位置和 stable locator；离线脑图仅展示可读出处，不承诺离线 PDF 内嵌。

### 6. 独立范围标记，不插入文字节点

词汇暖金点线为已确认决策；深度解读蓝实线、自定义问答灰紫虚线作为规划默认，确认本规划即采用。hover/focus 仅短暂浅底纹，不常驻整段色块。提供 marker 显示开关；同范围多个记录在同一入口按类型／时间列出，点击只读，明确用户另行重试才调模型。

将记录锚点解析为文字层中的 Range，再生成 page-local 几何片段，由独立 decoration 层绘制线和命中区域，不改 PDF.js 原始 text nodes、字体或 transform。重叠时保留词汇点线，段落转页边指示，不堆叠线；命中区域不能遮挡正常拖选。键盘入口集中呈现范围与记录，避免每个小线段制造重复 tab stop。

冻结 quote 中保存 document hash、页跨度、可用 offset、前后文；坐标只作为当前渲染结果而非跨缩放的权威锚点。兼容缓存和历史消息去重，已完成记录才显示完整标记；不兼容／不完整记录在历史中保留明确状态。旧锚点只在唯一解析时标记；跨文本节点、换行和 Unicode 归一化须保持原字符偏移可追溯。

### 7. 几何先复现，再修复

使用中文短书与英文／符号密集片段，先记录无标记时 canvas glyph 与 PDF.js text-layer Range 的偏差，再加标记比较，区分基础文字层偏差与装饰导致的偏差。

逐项检查 PDF.js 版本配套 CSS、原始 transform、font family／font substitution／字体加载时机、canvas 输出 DPR 与 CSS viewport、像素舍入、浏览器字体最小字号、英文连字和 Unicode 映射对 advance 的影响。依据可复现实验修正共同页面坐标系统；文字内容恢复和字体度量不能混为一谈，保留既有无 OCR Unicode 回归。

resize、缩放、字体 ready、虚拟页重建后重新解析几何，并取消／忽略旧渲染结果；测试 pending render 时连续调整尺寸。必须先修正 text layer 基础偏移，独立 decoration 不能掩盖 native selection 仍偏移的问题。

**替代方案**：逐个关键词加硬编码偏移、统一换字体或把文字重画到 overlay 不能解决全局累计误差，且有新重影风险。优先复用 PDF.js 原生度量和正确 transform，只有明确证明必要时才添加局部、可验证的校正。

### 8. 开发评测闭环与验收门槛

verification.md 定义固定语料、冒烟、内容标注、截图、几何测量和持久化差分。先保存旧版基线，不用用户完整书库做测试。真实模型＋可控 MCP 资料的内容评测与真实互联网连通性分别运行。每次改 prompt／预算／检索后保留全部尝试和参数，按失败原因修订，相关组复测后跑固定回归。

至少 24 条中文质量案例，每条检查必要概念、条件和论证，不只 ID／首句／标题。事实、算术、必要限定、错误引用、遗漏关键机制属于阻断问题；表达偏好可以记录非阻断意见。每组调试至多三次同类修订，仍失败则暂停该路线查根因或更换策略，不循环抽样直到碰巧通过。未达语义门槛不得标记质量验收任务完成。

模型辅助评分只能补充人工检查，不能一票通过。正式输出仍是一名主 agent，不因评测而增加每问评审轮数。

## Risks / Trade-offs

- 详细回答增加 latency／tokens → 逐调用记录，保留流式、兼容缓存和按需证据，额度只在统一预算内调整。
- 复杂论断不能机械检测 → 固定反例＋真实输出人工审核；不声称用关键词或启发式实现通用事实验证。
- 旧分块已丢精确页界 → 从原页文本重建派生映射；重复文本或提取差异无法唯一定位时显式降级。
- 连字、空格和字体实际字形框与选区行框不同 → 分开测字符 advance、行定位和标记几何，不能把行框留白都算偏差或用宽松容差掩盖累计漂移。
- 多条段落记录会使页面拥挤 → 默认轻线、重叠转页边、显示开关、按页惰性计算。
- 范围装饰与浏览器拖选冲突 → 测试拖选、点击、跨行和键盘，装饰不改文字层、不截获普通选择手势。

## Migration Plan

1. 保留旧提交作为基线，隔离数据复现并备份，记录旧记录／文件哈希及 schema。
2. 增量添加版本化位置／锚点元数据与必要存储迁移，兼容旧 SourceReference；不自动改变历史答案正文。
3. 安全重建派生 chunk／FTS 和位置解析缓存，验证数量、查找和幂等，保留旧引用 ID 可解析。
4. 新 prompt／深度版本不复用旧单句缓存；旧条目仍可手动查看，用户明确再生成才新增模型调用。
5. 新前端显示依赖位置状态，旧数据未修复时不伪报准确页码；新标记可隐藏，不影响原 PDF 阅读。
6. 回退时使用部署前备份恢复旧 schema／索引并回到旧代码；不得直接以旧代码写入不兼容的新 schema。新建用户笔记需另行保全，不用备份覆盖后续用户产物。
