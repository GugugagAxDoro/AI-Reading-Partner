## Why

当前实现把“开头简洁”收紧为单句或短段，缺少帮助理解的机制、例子与边界；有效引用 ID 也不能保证论断受支持或点击位置正确。实际增长投资案例暴露了跨页片段沿用章节起始页的问题，阅读标记与选区在英文、符号混排时另有待复现的坐标偏差。

## What Changes

- 默认提供“直接结论＋充分解释”：词汇以一句话定义开头，深度解读以短段开头，随后解释机制、例子、用途、假设和局限；按内容需要组织，不凑固定模块，也不把简洁误解为单句结束。
- 区分作者原意、解释完整性与事实可靠性。针对外部知识缺口、可疑／片面／过时论断按需联网核验，综合可信证据；本书与网页均非天然权威，保留会话禁网、预算与引用边界。
- 引用展示由候选序号改为书本图标＋`P41`／`P41–42`，网页为地球图标＋简短标题（过长省略，无标题使用域名）；详情、键盘访问、安全打开和来源 ID 保留。
- 修复 chunk 与摘录的真实页码／段落定位；安全修复可唯一解析的旧引用，无法确定时标记位置待核实，不把章节起始页当作引用页码。
- 已解释词汇采用暖金点状下划线；深度解读和自定义问答增加不同的原文标记，可直接打开已有记录。段落样式采用推荐的蓝色实线／灰紫虚线作为本提案默认方案，等待规划确认。
- 独立复现并修复文字层、选区和标记的几何偏差；不使用 OCR、不重复绘制文字，不将更换底纹当作文字层对齐修复。
- 增加固定内容级评测、版本前后真实输出对比和有界调试回归，覆盖事实准确性、解释充分性、引用支持度、定位与混排几何；保留失败记录，不以格式通过代替质量验收。

## Capabilities

### New Capabilities

无。本轮改进已有能力，不新增通用评审 agent 或其他独立产品模块。

### Modified Capabilities

- `reading-answer-contract`: 直接开头后的默认详细解释、关键条件保留和内容质量验收。
- `evidence-synthesis`: 批判性核验、来源质量判断及真实证据位置与论断支持度。
- `markdown-presentation`: 页码／网页信息引用标签、截断、来源详情及历史兼容。
- `pdf-reader-workspace`: 三类历史标记、记录访问、文字层与选区／标记对齐。
- `ai-reading-assistance`: 快捷解释的内容深度、版本与缓存兼容、历史记录标记的持久化范围。

## Impact

- 服务端：prompt、阅读／研究回答出口、预算与模型输出额度、证据选择、PDF 分块与索引、旧数据兼容解析。
- 共享包与存储：来源位置、字符／页边界、记录锚点和缓存兼容元数据；保留旧记录及必要备份，不自动重生成或覆盖用户内容。
- 前端：共享 Markdown 引用组件、PDF 文字层和独立标记、已有问答记录入口；沿用素色专业风。
- 验收：隔离中文短 PDF、可控 MCP 后端、真实模型和真实搜索分别报告；截图与 DB／文件增量，测试、配置、用户书籍及产物仍排除在 Git 外。
- 不包含 OCR、翻译、手机真机验收、多 agent、强制每问联网或自动无限质量重试。此次只生成规划，确认后另行实现；新规划不并入旧变更提交。
