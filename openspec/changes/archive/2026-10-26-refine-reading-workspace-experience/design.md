## Context

动机见 proposal.md。当前 React 阅读页将 PDF 渲染、缓存标记、笔记、小结和两种 AI 表单集中在一个组件中；回答状态只保留当前结果。后端已有选区模板、上下文分配、缓存、研究运行记录和模型文本流，但缺少持久化会话及其流生命周期。Markdown 目前为纯文本或简易按行解析。

本轮只产出规划。主规范、应用代码、数据库和模型配置不在规划阶段修改。已确认 Demo 是视觉参考，不是可调用真实模型的应用实现。

## Goals / Non-Goals

**Goals:**
- 在不重建 PDF 渲染引擎的前提下，增加可恢复的对话状态和稳定的选区／消息关联。
- 用同一上下文管线覆盖快捷解释、独立问答、显式追问与研究入口，保持缓存和证据语义。
- 用可测的状态、预算、语义 DOM 和持久化断言替代仅凭截图验收。

**Non-Goals:**
- 按用户 2026-10-26 的范围调整，本次不包含手机真机、系统中文输入法和实际软键盘验收；保留响应式视口、焦点和 composition 事件自动验证。
- 不改 PDF 原文映射、不引入 OCR、向量库、全文上传、自动模型会话摘要或无限历史回放。
- 不要求数学公式／Mermaid 的扩展语法解析、任意 HTML、在线图片加载、深色主题或手机系统选区菜单替换。
- 不把全部旧缓存、Agent 运行或旧答案伪造成迁移前不存在的历史会话；原记录仍可查看。

## Decisions

### 1. 对话为持久化业务实体，不只是气泡外观

新增 conversations、conversation_messages 和 reader_preferences 的增量迁移。会话归属项目和书籍，消息保存 role、action、Markdown、状态、顺序、引用快照、parent message IDs、request ID、attempt/retry relation、模板版本、缓存来源、模型／来源信息和有效预算。项目删除时会话随项目清理；文档永久删除时保留书名／hash／引用快照和对话，文档关联置空，禁止向不存在的书籍继续取证；同 hash 重导入时验证项目关联后恢复引用。

消息按会话游标分页，初次读取最近 50 条，向上加载不改变滚动锚点。每个会话至多一个活动生成；request ID 在会话内唯一。同一 ID 重发返回既有消息，不重复调用模型。不同会话可各有任务，切换会话不终止后台任务。只用 React 状态或 localStorage 存历史的方案不能满足恢复和后端上下文校验，因此不采用。

建议 API 边界：项目／文档下的 conversations 列表和创建；conversation messages 列表和发送；message events 订阅、cancel 和 retry。服务端逐级检查归属，不允许客户端提交任意 parent 原文作为可信历史。阅读偏好提供独立读写接口，不写入存储密钥的 providers.toml。

### 2. 流协议与持久化状态机

发送请求先事务写入用户消息和 pending 回答，再返回稳定 ID；事件订阅使用 SSE，事件包括 snapshot、delta、status、sources、error，均含 conversation/message ID 和单调序号。首次连接及重新连接先发送持久化快照，客户端替换而非拼接快照，再应用后续序号，防止重复字串。事件注册与快照读取需有一致游标边界，避免两者间漏字。

状态迁移为 pending -> streaming -> completed/cancelled/failed；只允许一次终态提交。按时间／大小合并保存局部输出（初始目标 500ms 或 4KB，终态立即保存），不逐 token 写 SQLite。取消通过 AbortController 传到模型和研究调度，已执行的笔记创建／小幅追加不会假装撤销；取消后不再启动新工具。断开浏览器连接不等于取消，刷新后可重新订阅；服务重启将孤立的活动状态转为 failed/interrupted 并保留已保存文本。终态后丢弃迟到事件。

不支持流的提供方仅在明确“流不支持”、尚未输出时走一次非流回退；认证失败、限流、超时和已输出的连接中断不自动重新调用模型。取消只承诺本地状态和尽力终止上游，不承诺撤回供应商费用。

### 3. 历史策略与预算

默认 smart：模板动作和独立问题为零历史；使用“追问”关联某个 completed 回答时，取该回答及其用户问题这一轮。比较模式最多显式关联两个 completed 回答。none 总是零历史；recent-one 仅对未显式关联的普通问答选同会话最近一轮。模板始终零历史，缓存浏览不改变关联。

偏好默认 historyMaxRounds=1、historyMaxTokens=1000；允许 rounds 0..2、tokens 0..1500，零预算或零轮数均关闭历史。比较两个回答需用户将轮数设为 2。UI 用“智能关联／不携带历史／最近一轮”，高级设置解释有效上限；配置持久化，后端校验，不静默接收非法范围。

初始应用输入预算：模板动作 3000 token，普通／追问 6000 token；输出预留默认 1200 token，安全余量 512 token。有效输入上限取应用预算与提供方 context_window 减输出、安全余量后的较小值。研究的每轮规划／工具消息同样受其已有配置及有效模型窗口约束，历史预算不能绕过研究轮数和每轮 token 上限。

计数对象是实际消息序列，包括 system、模板指令、当前问题、选区、历史、局部内容、检索和包装开销；选区不在模板和 evidence 中重复加入。优先保护系统约束、当前问题、原文，随后放必要标题／定位和相关证据，最后放有限历史。历史轮次超过预算时确定性截取答案片段并显式标记省略，不把未完成答案作为事实；若关键追问对象不足以理解，提示用户补充问题，不猜测。可移除低优先级上下文，但不能静默截断当前问题和关键选区；仍超限则在模型调用前拒绝并提示缩小范围。

使用现有估算器并增加消息包装安全开销；提供方有可用 tokenizer 时优先精确计数。测试同时验证估算预算和伪提供方实际收到的消息。不会为每条记录额外调用模型分类或生成历史摘要。

### 4. 模板、缓存与 Agent 适配

名词解释强调语境定义、必要背景和易混概念；深度解读强调观点、推理、假设和难点，不等同联网研究。模板放服务端版本化，消息记录版本。输入框附选区时快捷按钮立即发送；无选区可以直接询问本书。

独立名词／段落继续使用既有缓存。追问和比较本轮先绕过共享解释缓存，不新增复杂的历史缓存键。旧缓存可作为历史解释查看；新模板不自动覆盖旧消息，显式重新生成产生独立 attempt 并记录版本。只有成功完成的解释可写缓存；取消／失败和无效消息不写缓存。

统一 composer 调用既有意图路由与研究服务，联网开关属于会话，默认允许按既有规则自动触发；禁用时同时阻止 search 和 fetch。深度研究显式入口可放 composer 菜单。研究 timeline 默认折叠，确认重写／删除、保存笔记、生成脑图都归属相应消息；模型无配置、搜索无配置、执行失败仅影响相关能力。

### 5. 前端拆分与 Markdown

将 ConversationPanel、MessageList、MessageItem、Composer、SelectionQuote、SelectionActionPopover、MarkdownContent 和 NotePanel 作为阅读页的局部边界，避免继续扩大单页状态。服务请求、会话归属和流合并有独立逻辑；不同会话按 ID 管理草稿、选区、追问目标及异步状态。

Markdown 使用 react-markdown + remark-gfm，不使用手写按行解析，不启用 raw HTML。自定义 URL 白名单和 link/source handlers；普通 http/https 外链安全打开，内部 stable links 先解析并验证目标，javascript/data/file 等不能作为可执行链接。图片默认显示受控占位，不自动产生远程请求。表格／代码自身滚动，图片、长 URL 和长单词不能撑宽栏位。流式未闭合语法通过同一组件容错展示，不修写保存原文。

笔记默认阅读，显式进入编辑后展示源码，保存沿用既有版本和文件写入，取消不写数据库。小结默认展开全书宏观总结与当前章节，其余可折叠；所有状态使用中文，并保留独立重试入口。

### 6. 选区快照与气泡定位

使用 PDF.js DOM 文本层和 Selection/Range 矩形。selection snapshot 独立保存完整 quote、实际来源页、书籍 hash、prefix/suffix、normalized text、offsets/hash；发送使用 snapshot.page，不用 currentPage。跨页选区以起始页为主锚，保存结束页及每页片段；不能作为普通单页段落缓存命中，跨页动作先绕过段落缓存。

桌面用户完成选取后，取释放位置附近的可见矩形定位浮层，容器使用阅读区约束，靠上优先、空间不足向下并 clamp。pointerdown/focus 不先破坏冻结快照，按钮点击只提交一次。滚动、重选、Esc 或选区取消关闭浮层；已附加的 composer 引用由单独关闭按钮移除。键盘选取使用可见 range 矩形并保留侧栏操作；移动端先使用 composer 快捷入口，不抢系统原生长按菜单。

引用单行省略不是 CSS 尾部 ellipsis：使用 Intl.Segmenter 的 grapheme 和测量宽度，保留首尾、二分调整中间省略，ResizeObserver 在栏宽变化时重算。完整内容放可键盘／触摸展开的预览，页码和移除按钮不参与被裁切文本。无省略需求不添加省略号，任何展示截取都不改变引用快照。

### 7. 视觉与响应式约束

参考已确认侧栏 Demo 的布局和色彩，不依赖开发者机器上的绝对路径。使用共享样式 token：背景灰白、主文字石墨、低饱和青绿交互强调，错误／警告采用明确状态色与文字；普通圆角 4..6px，不超过 8px。使用 Lucide 图标和 tooltip；小结、会话、编辑区域不重复套卡片。

桌面（初始断点 1200px）三栏可调：左栏 220..360px、右栏 340..480px、中心尽量至少 480px；不足时自动切为抽屉而非挤压 PDF。断点以下目录和对话为互斥抽屉，背景 inert、焦点约束、关闭后恢复焦点与阅读位置，适配软键盘和动态可视高度。面板偏好先存本地；无效旧宽度 clamp，不影响已存会话和书籍。桌面栏宽和 mobile drawer 均需通过真实尺寸和截图验收，不能只检查 media query 是否存在。

书库增加项目内标题筛选和稳定排序，最近阅读无记录时按添加时间／ID 作稳定回退；封面 object-fit: contain。主要动作是打开／继续阅读，重试、移出、永久删除进入菜单，删除沿用确认和后端语义。读书位置恢复、缓存标记、目录跳转、笔记和脑图是必须保留的回归项。

## Risks / Trade-offs

- [消息永久保留但上下文很少，可能无法理解模糊的“这个”] -> 明确追问关联和引用预览；必要时请用户补充，不偷偷携带整个聊天。
- [估算 token 与提供方不同] -> 对实际序列计数、预留安全余量、提供方超长错误不反复重试；不能宣称对未知 tokenizer 精确。
- [流断开／切会话导致重复或错位] -> 服务端快照和序号、request ID、会话隔离、幂等终态测试。
- [选区菜单破坏选区或在缩放后漂移] -> 冻结 snapshot、阅读区边界、缩放和滚动测试，移动端暂不替换原生菜单。
- [安全 Markdown 限制旧笔记中的 HTML／图片] -> 保留 Markdown 原文，展示安全降级和图片占位，不在迁移时删内容。
- [局部输出持久化增加写入] -> 小批量合并刷新和分页；终态原子写入，不为每个 token 启动事务。
- [视觉改版掩盖行为回归] -> 截图与模型请求／SQLite／文件证据配对，测试方法见 testcases.md。

## Migration Plan

1. 先新增表和索引，事务迁移、可重复执行；升级前备份用户数据库，不扫描或上传书籍与配置。
2. 增加对话和流 API，再接入前端；保持既有动作 API、缓存和 Agent 接口兼容直至新流程验收。
3. 仅新交互写入会话；已有小结、笔记、缓存和进度不做内容性重写。
4. 用独立临时数据目录完成生成式 fixture／模型替身测试，必要时用用户自备样本补充，证据留在被忽略的 artifacts 下。
5. 出现问题回退 UI 和入口开关，保留新增会话数据，不执行 DROP 或覆盖原数据库；恢复旧备份前先另存升级后的数据并征得用户同意。
