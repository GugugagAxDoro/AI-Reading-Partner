## Why

当前阅读请求默认联网，研究流程存在重复检索、上下文与调用预算不统一、回答出口不一致的问题，增加延迟与 token 消耗，也容易把无关证据混入回答。需要将检索改为由证据缺口驱动，通过 MCP 统一接入搜索，并以直接、简洁的回答和可定位引用提升阅读体验。

## What Changes

- 使用单一逻辑主 agent 和受约束的 harness：简单问题直接回答，确有信息缺口时才进入有界工具循环，不为每个请求强制增加规划或评判调用。
- **BREAKING（检索策略）**：以默认 `auto` 的按需联网替代默认强制联网；保留会话关闭联网的硬限制。当前书优先，必要时检索项目内其他书；明确要求联网、时效性问题和本地无法解释的外部事实允许直接触发联网，不机械耗尽全部本地检索。
- 通过应用侧 MCP client 与本地 stdio 搜索 server 接入 SearXNG，并提供受控网页读取；继续支持 OpenAI-compatible 模型和无原生工具调用时的结构化计划降级，不要求模型供应商原生支持 MCP。
- 引入按问题组织的证据包：同义事实合并，重复转载不充当独立佐证，互补信息整合，冲突按定义、时间、条件和方法比较，无法解决时保留差异。
- 将 prompt 拆为基础约束、检索/证据策略、任务模板、输出契约和不可信数据层，并记录独立版本。所有最终回答出口使用同一契约，不以全文后处理删除句子来伪造合规。
- 词汇解释以“词汇：定义”直接开头，深度解读以简短结论段开头；删除无意义引导语、来源口播和模板化转折，按需展开，不凑模块。
- 统一本地与网络 reference：以书本/地球图标区分，点击定位书籍页码/段落或打开网页；来源说明交给引用，必要的限定、不确定性和冲突仍直接表达。历史 Markdown 和失效引用保持可读。
- 统一上下文、调用次数、总时限、取消、无进展停止、运行记录和 token 核算；缓存增加语义、版本、联网策略及证据新鲜度兼容性判断，避免旧答案掩盖必须检索的问题。
- 补充可复现的单元、集成、端到端和模型质量评测场景，明确冒烟集合、截图与本地持久化验证；真实模型/搜索验证与离线确定性测试分开报告。

## Capabilities

### New Capabilities

- `mcp-search-integration`: 应用侧 MCP 搜索/网页读取边界、SearXNG 接入、生命周期、安全和错误降级。
- `evidence-synthesis`: 按问题覆盖的证据管理、检索需求判断、去重、互补融合、冲突分析和来源有效性。
- `reading-answer-contract`: 分层版本化 prompt、直接开头、简洁表达、共享回答出口与流式兼容校验。

### Modified Capabilities

- `research-agent`: 按需检索替换强制预取；有界 harness、工具协议完整性、运行记录、全调用预算与最终回答一致性。
- `ai-reading-assistance`: 普通问答与快捷操作共享按需联网策略，最小上下文、兼容缓存和摘要忠实性。
- `markdown-presentation`: 所有相关 Markdown 展示使用统一图标 reference，支持定位、可访问性、历史兼容与安全降级。
- `provider-configuration`: 通过本地配置管理应用自有 MCP 搜索 server 与现有 SearXNG，保持模型分层、协议兼容及密钥隔离。

## Impact

- 服务端：`apps/server/src/services/agent.ts`、`conversations.ts`、`prompts.ts`、意图路由、检索、缓存、搜索、网页抓取、配置和运行记录服务。
- 共享包：`packages/ai` 的模型/用量封装，`packages/core` 的上下文与证据结构，`packages/db` 的引用、缓存和运行元数据兼容迁移。
- 前端：共享 Markdown renderer、回答与笔记引用、会话运行状态和本地文档定位；沿用现有素色专业风，不重做整体布局。
- 新增官方 MCP SDK 依赖及应用自有搜索 server 启动入口；SearXNG 继续作为可自行部署的搜索后端，不引入付费搜索供应商或云端凭据托管。
- 不包含多 agent、任意代码执行、通用 MCP marketplace、远程 MCP 传输实现、OCR、移动真机验证或翻译功能。不改变笔记大幅重写/删除需要确认的边界。
- 仅产出本次规划文档；实现须由用户另行确认。密钥、用户书籍、真实测试产物及 `.codex` 不进入提交。
